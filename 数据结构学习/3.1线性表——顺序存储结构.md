### 1. 什么是顺序存储结构？（一句话定义）

**定义**：用**一组地址连续的存储单元**，依次存放线性表中的数据元素，使得**逻辑上相邻**的两个元素，在**物理位置（内存）上也是相邻的**。

**大白话**：就像电影院的**一排连续座位**，第1个座位挨着第2个，第2个挨着第3个……整个线性表就是这段连续内存空间里的一串数据。

---

### 2. 核心特征（逻辑 + 物理的双重映射）

|维度|特征|说明|
|---|---|---|
|**逻辑关系**|**一对一**（线性）|除第一个元素外，每个元素有且仅有一个直接前驱；除最后一个外，有且仅有一个直接后继。|
|**物理存储**|**地址连续**|元素在内存中紧挨着存放，中间没有空隙。|
|**访问方式**|**随机存取（Random Access）**|只要知道起始地址和元素下标，通过公式 `Loc(a_i) = Loc(a_1) + (i-1) * size` 就能**瞬间**算出任意元素的地址，时间复杂度 **O(1)**。|

> 这个公式是顺序存储的**灵魂**，也是它比链表快的最根本原因。

---

### 3. 顺序存储的“身份证”—— 起始地址 + 下标

在C语言里，顺序表通常用**结构体**来表示：

c

#define MAXSIZE 100   // 预分配的最大容量
typedef struct {
    int data[MAXSIZE];  // 用数组存放数据
    int length;         // 当前实际存储的元素个数
} SqList;               // SqList = Sequence List

**关键点**：

- `data` 是存储空间的起点（基地址）。
    
- `length` 告诉你有多少个元素是“有效的”。
    
- 即使 `MAXSIZE = 100`，如果 `length = 5`，只代表前5个位置有数据，后面的95个位置是空闲的（但内存已经被占用了）。

### 4. 基本操作的效率（面试/考试必问）

我把最核心的四个操作拎出来，你直接看**时间复杂度**就懂它的脾性了：

|操作|实现方式|时间复杂度|为什么？|
|---|---|---|---|
|**查找（按下标）**|`arr[i]` 直接访问|**O(1)**|公式一算，地址直接得到（随机存取）|
|**查找（按值）**|从 `arr[0]` 开始逐个比较|**O(n)**|最坏情况遍历整个表|
|**插入（在位置 i）**|将 i 及后面的元素**全部后移**一格，再插入新元素|**O(n)**|平均要移动一半的元素（数据搬运量大）|
|**删除（在位置 i）**|将 i 后面的元素**全部前移**一格，覆盖掉被删元素|**O(n)**|同样需要大量搬运|

> **核心记忆点**：**顺序表“查询快如闪电，插入删除慢如蜗牛”**（因为要挪动大量元素）。

---

### 5. 优点和缺点（工程选型决策表）

|维度|详细说明|
|---|---|
|**优点（为什么用它）**|1. **随机存取**：按下标访问极快（O(1)）。  <br>2. **存储密度高**：只存数据本身，不需要额外指针（链表的指针要占额外空间）。  <br>3. **CPU缓存友好**：连续内存，遍历时CPU可以预读数据，极快。|
|**缺点（什么时候避开它）**|1. **插入/删除效率低**：大量数据移动（O(n)）。  <br>2. **空间固定**：预先分配最大容量，容易浪费（分配多了）或溢出（分配少了，需要扩容）。  <br>3. **扩容代价高**：动态扩容时，要申请新空间并拷贝所有旧数据（耗时）。|

---

### 6. 一句话总结（帮你定位）

> **顺序存储 = 数组的“封装版”**，它继承了数组的一切优点（快）和缺点（挪动麻烦），是**静态数据**（如学生名册、每周天气数据）的最佳选择；但如果你的业务是**频繁增删**（如银行排队、文本编辑器），立刻放弃它，转投链表。

## 分支六：线性表的顺序存储结构
### （一）定义
- 用连续内存存放线性表元素，逻辑相邻 = 物理相邻
### （二）核心公式
- Loc(a_i) = Loc(a_1) + (i-1) * sizeof(元素)
### （三）数据结构（C语言）
- 静态数组 + 当前长度（length）
### （四）操作复杂度
- 按下标查找：O(1)  —— 最快
- 按值查找：O(n)
- 插入/删除：O(n)  —— 最慢（大量移动）
### （五）优缺点
- ✅ 优点：随机存取、存储密度高、缓存友好
- ❌ 缺点：增删慢、空间固定/扩容麻烦
### （六）适用场景
- 数据量稳定、查询频繁、极少增删（如：学籍管理系统、静态配置表）


Q：为什么说顺序存储结构会造成**存储空间的“碎片”？**

A：**核心结论先给你**：**顺序存储本身不会产生碎片，但它会因为“静态分配”和“动态扩容”这两种机制，间接导致内存中出现无法利用的“碎片”**。换句话说，顺序表是**“碎片的受害者”**，而链表是**“碎片的收割机”**。

我分两个层面帮你彻底讲透：

---

### 层面一：静态顺序表（固定大小）—— 产生“内部碎片”

当你使用 `int arr[100]` 这种静态分配时，操作系统会一次性给你划出**一整块连续的地盘**（比如 400 个字节）。

**问题来了**：如果你的业务只存了 5 个有效数据（`length = 5`），那剩下的 95 个位置（380 个字节）**虽然空着，但你既不能把它还给操作系统，也不能拿它去存别的变量**。

| 碎片类型                             | 人话解释                                                 | 顺序表里的体现                                           |
| -------------------------------- | ---------------------------------------------------- | ------------------------------------------------- |
| **内部碎片（Internal Fragmentation）** | 分配给你的地盘，你自己没用完，但又**不肯还**，导致这片空闲空间被锁死，别人没法用。（占着茅坑不拉屎） | 你申请了 100 个位置，只用了 5 个，剩下 95 个位置**闲置但不可用**，这就是内部碎片。 |

> **生活类比**：你租了一辆核载 50 人的大巴车（顺序表），结果只来了 5 个乘客。剩下 45 个座位空着，但出租车司机不能把这 45 个座位拆下来租给别人。这 45 个空座就是**内部碎片**。

---

### 层面二：动态顺序表（动态扩容）—— 产生“外部碎片”

这是你问题的真正核心！我们以 Java 的 `ArrayList` 或 C++ 的 `vector` 为例，它们采用**“倍增扩容”**策略：

1. 初始分配 10 个位置。
    
2. 当存满第 11 个元素时，系统**重新申请一块更大的连续空间**（比如 20 个位置），并把旧的 10 个元素**全部拷贝**过去。
    
3. 然后**释放**旧的 10 个位置的内存。
    

**问题来了**：被释放的旧空间（10个位置）还给了操作系统。但经过无数次扩容和释放，内存中就会布满大大小小的**“空闲洞”**（hole）。

| 碎片类型                             | 人话解释                                                                             | 动态顺序表扩容时的体现                                                                                                          |
| -------------------------------- | -------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| **外部碎片（External Fragmentation）** | 内存里到处是**大小不等、不连续**的空闲块。虽然这些空闲块的总和足够大，但因为**不连续**，无法满足一个大数组的连续内存申请。（此时可否采取链式存储结构？） | 经过多次扩容，内存中散布着 8KB、15KB、7KB 等小空闲块。此时你想申请一块 20KB 的连续空间，虽然总空闲内存有 30KB，但因为**没有一块连续的 20KB**，申请失败！这 30KB 就成了**无法利用的外部碎片。** |
|                                  |                                                                                  |                                                                                                                      |

> **生活类比（拼图）**：停车场里到处是零散的空车位，东一个西一个。虽然空车位总数有 20 个，但你的车队要求**必须连在一起的 10 个车位**才能停。这些零散的空车位就是**外部碎片**——看得见用不上。

---

### 层面三：顺序表 vs 链表 —— 碎片处理能力对比（升华）

为了让你彻底理解为什么链表不怕碎片，我把它们放在一起 PK：

|特性|**顺序表（数组）**|**链表**|
|---|---|---|
|**内存申请方式**|一次性申请**一大块连续**空间。|每次只申请**一个小块**（一个节点），不要求连续。|
|**对碎片的态度**|**极度敏感**：哪怕总空闲内存很大，只要不连续，就申请失败。|**极度宽容**：任意大小的碎片（哪怕只有 8 字节）都能被链表节点利用。|
|**碎片产生机制**|**制造碎片**：动态扩容时释放的旧空间，会制造外部碎片。|**利用碎片**：链表把碎片像“拼图”一样全部串起来，化废为宝。|
|**内部碎片**|有（分配多了用不完）。|**几乎没有**（用多少申请多少，节点大小刚刚好）。|

---

### 4. 实战场景：你什么时候会真正感受到“碎片”？

- **在 PC/服务器上**：内存动辄 16GB/128GB，碎片问题**几乎无感**（虚拟内存和页式管理帮你兜底了）。
    
- **在嵌入式系统（如智能手表、路由器）**：内存只有几十 KB 到几 MB，且**长时间运行不重启**。如果频繁使用动态数组（如 `ArrayList`）不断扩容，很快就会因为**内存碎片**导致 `malloc` 失败，系统直接死机。此时，链表反而是更安全的选择。

## 分支七：存储空间的“碎片”问题
### （一）内部碎片（Internal Fragmentation）
- 定义：分配给你的空间，你自己没用完，但又不让给别人用。
- 顺序表场景：静态数组 `arr[100]` 只存了 5 个元素，剩下 95 个位置空置浪费。
### （二）外部碎片（External Fragmentation）
- 定义：内存中分散着许多不连续的小空闲块，总和够大，但不满足连续大空间申请。
- 顺序表场景：动态扩容时释放的旧空间，久而久之把内存切碎。
### （三）链表的“降维打击”
- 链表不要求连续，任何碎片都能塞下一个节点。
- 空间利用率高，几乎没有内部碎片和外部碎片问题。
### （四）工程决策
- 大型系统（内存充足）：用顺序表（数组/ArrayList），速度快，碎片交给 OS 管理。
- 嵌入式/实时系统（内存紧张）：用链表或自定义内存池，避免碎片累积导致崩溃。
