### 1. 时间复杂度和空间复杂度（算法的“体检报告”）

| 度量维度      | 官方定义                                   | 人话翻译                                         | 考察对象     |
| --------- | -------------------------------------- | -------------------------------------------- | -------- |
| **时间复杂度** | 算法中基本操作重复执行的次数，是问题规模 `n` 的某个函数 `T(n)`。 | **跑得有多快？**  <br>比如处理 10 万个数据，需要多少步（不关心具体秒数）。 | CPU 计算时间 |
| **空间复杂度** | 算法在执行过程中所需额外存储空间的度量，是 `n` 的函数 `S(n)`。  | **吃内存有多少？**  <br>除了输入数据本身，算法运行时还需要额外占多少内存。   | 内存占用     |

**注意**：我们度量的不是“绝对时间（毫秒）”和“绝对内存（MB）”，因为那取决于计算机硬件（CPU主频、内存大小）。我们度量的是**“步骤数”**和**“额外空间数”**，与机器无关。

### 2. 大O表示法（Big O Notation）—— 算法的“望远镜”

这是算法效率度量的**灵魂工具**。你只要记住它的核心思想：**忽略常数项和低阶项，只关注“增长趋势”。**

**数学定义**：  
若存在常数 `c > 0` 和 `n0 > 0`，使得当 `n ≥ n0` 时，`T(n) ≤ c * f(n)`，则称 `T(n) = O(f(n))`。

**人话翻译**：  
当数据量 `n` 变得非常大时（比如从 100 变到 100 万），算法执行步骤的增长趋势是什么？我们只看**最高次幂**，把所有的系数、常数、低次幂全部扔掉。

**大O表示法的“砍砍砍”规则**：

|原始函数 T(n)|大O表示 O(f(n))|砍掉的部分|
|---|---|---|
|`3n + 2`|**O(n)**|砍掉常数 `3` 和 `2`，只看 `n`|
|`5n² + 3n + 1`|**O(n²)**|只看最高次 `n²`，砍掉系数 `5`、低次 `3n` 和常数 `1`|
|`2^n + n^10`|**O(2^n)**|指数函数增长远快于幂函数，只看 `2^n`|

### 3. 常见时间复杂度“速度排行榜”（从快到慢）

这是面试笔试的**高频考点**，你必须像背乘法口诀一样记住它们：

|大O表示|算法名称（举例）|数据量 n=100 时的操作数（估算）|数据量 n=10万 时的操作数|评价|
|---|---|---|---|---|
|**O(1)**|常数阶（数组随机访问）|1 步|1 步|**神速**，与数据量无关|
|**O(log n)**|对数阶（二分查找）|≈ 7 步|≈ 17 步|**极快**，数据量翻万倍，只多走几步|
|**O(n)**|线性阶（简单查找最大值）|100 步|10万 步|**常规**，数据量大就线性变慢|
|**O(n log n)**|线性对数阶（归并排序、快排）|≈ 700 步|≈ 170万 步|**优秀排序算法的天花板**|
|**O(n²)**|平方阶（冒泡排序、选择排序）|1万 步|100亿 步|**灾难**，数据量稍大就卡死|
|**O(2^n)**|指数阶（穷举子集、汉诺塔）|约 10^30 步|宇宙毁灭都算不完|**噩梦**，只适用于极小数据量|
|**O(n!)**|阶乘阶（穷举排列）|9.3×10^157 步|想都别想|**终极噩梦**，几乎不可用|

**增长趋势可视化（心理图像）**：

- **O(1)** 就像**电梯直达**，无论几楼，按下按钮瞬间到。
    
- **O(log n)** 就像**翻字典**，每次翻一半，飞速逼近目标。
    
- **O(n)** 就像**清点一排货架**，货架越长，点得越久。
    
- **O(n²)** 就像**两两对比所有商品**，货架长一倍，工作量翻四倍（直接爆炸）。

### 4. 空间复杂度（吃内存的“胃口”）

大部分初学者只关注时间，忽略了空间。但在**嵌入式系统（内存只有几KB）**或**超大数组（亿级数据）**中，空间复杂度是致命因素。

**两种典型的空间复杂度**：

|空间复杂度|含义|举例|
|---|---|---|
|**O(1)**|**原地工作**：算法只需要额外几个变量，不随数据量变化。|冒泡排序、插入排序（只用一个临时变量`temp`）。|
|**O(n)**|**线性额外空间**：需要额外申请一个和输入一样大的数组。|归并排序（需要额外数组来合并）、递归求阶乘（栈深度为n）。|

**递归算法的空间复杂度陷阱**：

c

int factorial(int n) {
    if (n == 1) return 1;
    return n * factorial(n - 1);
}

- **时间复杂度**：O(n)（调用 n 次）
    
- **空间复杂度**：O(n)（因为递归调用会在栈上压入 n 个函数帧，每个帧占用内存）
    

> 所以，递归虽然写起来优雅，但**吃内存**。如果数据量极大，递归会导致**栈溢出（Stack Overflow）**，这时候就要改成迭代（循环）版本，让空间复杂度降到 O(1)。

### 5. 时间与空间的“残酷交易”（Trade-off）

算法设计里没有“既要又要”，你必须在时间和空间之间做抉择：

|策略|做法|典型算法|
|---|---|---|
|**空间换时间**|多占点内存，把数据预处理成哈希表/缓存，换区极速查询。|**哈希查找**：`O(1)` 时间，但占用 `O(n)` 空间来存哈希表。|
|**时间换空间**|少占点内存，每次现场计算，牺牲一点速度。|**递归斐波那契**：`O(1)` 空间，但时间复杂度是恐怖的 `O(2^n)`。|

**经典面试题**：设计一个算法，判断一个字符串里的字符是否全部唯一（没有重复字符）？

- **方案A（时间换空间）**：两层循环暴力比较，时间复杂度 O(n²)，空间 O(1)。
    
- **方案B（空间换时间）**：用一个长度为256的布尔数组记录出现过的字符，时间复杂度 O(n)，空间 O(1)（因为256是常数，所以严格来说也算 O(1)空间）。**显然方案B更优**。

### 6. 实战推演：如何分析你的“找最大值”算法？

我们拿上一轮的 **V3 优雅版** 来练手：

c

bool findMax(int arr[], int n, int *result) {
    if (arr == NULL || n <= 0 || result == NULL) return false;  // O(1)
    
    int max = arr[0];                                            // O(1)
    for (int i = 1; i < n; i++) {                                // 循环执行 n-1 次
        if (arr[i] > max) max = arr[i];                          // 每次 O(1)
    }
    
    *result = max;                                               // O(1)
    return true;                                                 // O(1)
}

**时间复杂度分析**：

- 基本操作是 `if (arr[i] > max)` 比较和赋值。
    
- 循环执行 `n-1` 次，每次执行常数次操作。
    
- 总操作数 T(n) = `1（初始化） + (n-1) * 1（循环体） + 1（返回） = n + 1`。
    
- 忽略常数和低阶项 → **时间复杂度 = O(n)**。
    

**空间复杂度分析**：

- 算法只申请了一个整型变量 `max`（常数个）。
    
- 没有额外申请数组或递归调用。
    
- **空间复杂度 = O(1)**（原地工作）。
    

**结论**：这个算法在时间上已经是最优（因为无论如何你至少要看一遍所有数据），空间上也是最省的。所以它是一个**完美算法**。

## 分支四：算法效率度量（算法的“体检报告”）
### （一）时间复杂度（跑得多快）
- 定义：基本操作执行次数 T(n) 的增长趋势
- **大O表示法**（忽略常数和低阶项）：
  - O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2^n) < O(n!)
- 分析技巧：找循环最深处的操作，数循环嵌套层数
### （二）空间复杂度（吃得多少）
- 定义：算法运行时所需的额外内存
- 常见级别：
  - O(1)：原地工作（只用了几个变量）
  - O(n)：需要与输入同等规模的空间（如归并排序、递归栈）
### （三）取舍法则（Trade-off）
- 空间换时间（缓存、哈希表）
- 时间换空间（流式处理、递归）
