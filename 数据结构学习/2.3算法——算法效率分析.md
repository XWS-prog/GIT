### 1. 时间复杂度和空间复杂度（算法的“体检报告”）

| 度量维度      | 官方定义                                   | 人话翻译                                         | 考察对象     |
| --------- | -------------------------------------- | -------------------------------------------- | -------- |
| **时间复杂度** | 算法中基本操作重复执行的次数，是问题规模 `n` 的某个函数 `T(n)`。 | **跑得有多快？**  <br>比如处理 10 万个数据，需要多少步（不关心具体秒数）。 | CPU 计算时间 |
| **空间复杂度** | 算法在执行过程中所需额外存储空间的度量，是 `n` 的函数 `S(n)`。  | **吃内存有多少？**  <br>除了输入数据本身，算法运行时还需要额外占多少内存。   | 内存占用     |

**注意**：我们度量的不是“绝对时间（毫秒）”和“绝对内存（MB）”，因为那取决于计算机硬件（CPU主频、内存大小）。我们度量的是**“步骤数”**和**“额外空间数”**，与机器无关。

### 2. 大O表示法（Big O Notation）—— 算法的“望远镜”

这是算法效率度量的**灵魂工具**。你只要记住它的核心思想：**忽略常数项和低阶项，只关注“增长趋势”。**

**数学定义**：  
若存在常数 `c > 0` 和 `n0 > 0`，使得当 `n ≥ n0` 时，`T(n) ≤ c * f(n)`，则称 `T(n) = O(f(n))`。

**人话翻译**：  
当数据量 `n` 变得非常大时（比如从 100 变到 100 万），算法执行步骤的增长趋势是什么？我们只看**最高次幂**，把所有的系数、常数、低次幂全部扔掉。

**大O表示法的“砍砍砍”规则**：

|原始函数 T(n)|大O表示 O(f(n))|砍掉的部分|
|---|---|---|
|`3n + 2`|**O(n)**|砍掉常数 `3` 和 `2`，只看 `n`|
|`5n² + 3n + 1`|**O(n²)**|只看最高次 `n²`，砍掉系数 `5`、低次 `3n` 和常数 `1`|
|`2^n + n^10`|**O(2^n)**|指数函数增长远快于幂函数，只看 `2^n`|

### 3. 常见时间复杂度“速度排行榜”（从快到慢）

这是面试笔试的**高频考点**，你必须像背乘法口诀一样记住它们：

|大O表示|算法名称（举例）|数据量 n=100 时的操作数（估算）|数据量 n=10万 时的操作数|评价|
|---|---|---|---|---|
|**O(1)**|常数阶（数组随机访问）|1 步|1 步|**神速**，与数据量无关|
|**O(log n)**|对数阶（二分查找）|≈ 7 步|≈ 17 步|**极快**，数据量翻万倍，只多走几步|
|**O(n)**|线性阶（简单查找最大值）|100 步|10万 步|**常规**，数据量大就线性变慢|
|**O(n log n)**|线性对数阶（归并排序、快排）|≈ 700 步|≈ 170万 步|**优秀排序算法的天花板**|
|**O(n²)**|平方阶（冒泡排序、选择排序）|1万 步|100亿 步|**灾难**，数据量稍大就卡死|
|**O(2^n)**|指数阶（穷举子集、汉诺塔）|约 10^30 步|宇宙毁灭都算不完|**噩梦**，只适用于极小数据量|
|**O(n!)**|阶乘阶（穷举排列）|9.3×10^157 步|想都别想|**终极噩梦**，几乎不可用|

**增长趋势可视化（心理图像）**：

- **O(1)** 就像**电梯直达**，无论几楼，按下按钮瞬间到。
    
- **O(log n)** 就像**翻字典**，每次翻一半，飞速逼近目标。
    
- **O(n)** 就像**清点一排货架**，货架越长，点得越久。
    
- **O(n²)** 就像**两两对比所有商品**，货架长一倍，工作量翻四倍（直接爆炸）。

### 4. 空间复杂度（吃内存的“胃口”）

大部分初学者只关注时间，忽略了空间。但在**嵌入式系统（内存只有几KB）**或**超大数组（亿级数据）**中，空间复杂度是致命因素。

**两种典型的空间复杂度**：

|空间复杂度|含义|举例|
|---|---|---|
|**O(1)**|**原地工作**：算法只需要额外几个变量，不随数据量变化。|冒泡排序、插入排序（只用一个临时变量`temp`）。|
|**O(n)**|**线性额外空间**：需要额外申请一个和输入一样大的数组。|归并排序（需要额外数组来合并）、递归求阶乘（栈深度为n）。|

**递归算法的空间复杂度陷阱**：

c

int factorial(int n) {
    if (n == 1) return 1;
    return n * factorial(n - 1);
}

- **时间复杂度**：O(n)（调用 n 次）
    
- **空间复杂度**：O(n)（因为递归调用会在栈上压入 n 个函数帧，每个帧占用内存）
    

> 所以，递归虽然写起来优雅，但**吃内存**。如果数据量极大，递归会导致**栈溢出（Stack Overflow）**，这时候就要改成迭代（循环）版本，让空间复杂度降到 O(1)。

### 5. 时间与空间的“残酷交易”（Trade-off）

算法设计里没有“既要又要”，你必须在时间和空间之间做抉择：

|策略|做法|典型算法|
|---|---|---|
|**空间换时间**|多占点内存，把数据预处理成哈希表/缓存，换区极速查询。|**哈希查找**：`O(1)` 时间，但占用 `O(n)` 空间来存哈希表。|
|**时间换空间**|少占点内存，每次现场计算，牺牲一点速度。|**递归斐波那契**：`O(1)` 空间，但时间复杂度是恐怖的 `O(2^n)`。|

**经典面试题**：设计一个算法，判断一个字符串里的字符是否全部唯一（没有重复字符）？

- **方案A（时间换空间）**：两层循环暴力比较，时间复杂度 O(n²)，空间 O(1)。
    
- **方案B（空间换时间）**：用一个长度为256的布尔数组记录出现过的字符，时间复杂度 O(n)，空间 O(1)（因为256是常数，所以严格来说也算 O(1)空间）。**显然方案B更优**。

### 6. 实战推演：如何分析你的“找最大值”算法？

我们拿上一轮的 **V3 优雅版** 来练手：

c

bool findMax(int arr[], int n, int *result) {
    if (arr == NULL || n <= 0 || result == NULL) return false;  // O(1)
    
    int max = arr[0];                                            // O(1)
    for (int i = 1; i < n; i++) {                                // 循环执行 n-1 次
        if (arr[i] > max) max = arr[i];                          // 每次 O(1)
    }
    
    *result = max;                                               // O(1)
    return true;                                                 // O(1)
}

**时间复杂度分析**：

- 基本操作是 `if (arr[i] > max)` 比较和赋值。
    
- 循环执行 `n-1` 次，每次执行常数次操作。
    
- 总操作数 T(n) = `1（初始化） + (n-1) * 1（循环体） + 1（返回） = n + 1`。
    
- 忽略常数和低阶项 → **时间复杂度 = O(n)**。
    

**空间复杂度分析**：

- 算法只申请了一个整型变量 `max`（常数个）。
    
- 没有额外申请数组或递归调用。
    
- **空间复杂度 = O(1)**（原地工作）。
    

**结论**：这个算法在时间上已经是最优（因为无论如何你至少要看一遍所有数据），空间上也是最省的。所以它是一个**完美算法**。

## 分支四：算法效率度量（算法的“体检报告”）
### （一）时间复杂度（跑得多快）
- 定义：基本操作执行次数 T(n) 的增长趋势
- **大O表示法**（忽略常数和低阶项）：
  - O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2^n) < O(n!)
- 分析技巧：找循环最深处的操作，数循环嵌套层数
### （二）空间复杂度（吃得多少）
- 定义：算法运行时所需的额外内存
- 常见级别：
  - O(1)：原地工作（只用了几个变量）
  - O(n)：需要与输入同等规模的空间（如归并排序、递归栈）
### （三）取舍法则（Trade-off）
- 空间换时间（缓存、哈希表）
- 时间换空间（流式处理、递归）



# Specific：递归复杂度分析

### 1. 核心工具：递归方程（数学建模）

递归算法的时间，由两部分组成：

1. **递推部分**：每层递归需要消耗的时间（比如循环、比较）。
    
2. **递归调用部分**：调用了多少次自身，每次处理的数据规模是多少。
    

用数学公式表达，就是**递归方程（递推式）**：

T(n)=a⋅T(nb)+f(n)T(n)=a⋅T(bn​)+f(n)

| 符号       | 含义                                    | 举例                                        |
| -------- | ------------------------------------- | ----------------------------------------- |
| **T(n)** | 处理规模为 `n` 的数据所需的总时间                   | -                                         |
| **a**    | 每层递归**调用自身的次数**                       | 二分查找调1次；斐波那契调2次                           |
| **n/b**  | 每次递归调用时，**数据规模缩小为原来的 1/b**            | 二分查找/归并排序都是 `n/2`                         |
| **f(n)** | 在**当前这一层**，除了递归调用外，做其他操作（如比较、合并）所需的时间 | 二分查找的 `f(n)=O(1)`；归并排序的 `f(n)=O(n)`（合并数组） |

### 2. 实战推演：三大经典递归算法

#### （1）二分查找 —— 每次砍一半，只走一条路

c

int binarySearch(int arr[], int left, int right, int target) {
    if (left > right) return -1;               // O(1)
    int mid = (left + right) / 2;              // O(1)
    if (arr[mid] == target) return mid;        // O(1)
    if (arr[mid] > target) 
        return binarySearch(arr, left, mid-1, target);  // 只走一边！
    else 
        return binarySearch(arr, mid+1, right, target);
}

**递归方程建模**：

- `a = 1`：每次只递归调用**一次**（只走左或只走右）。
    
- `b = 2`：数据规模每次变成一半（`n/2`）。
    
- `f(n) = O(1)`：每层只做常数次比较和计算。
    

T(n)=1⋅T(n2)+O(1)T(n)=1⋅T(2n​)+O(1)

**解方程（代入法）**：

- T(n) = T(n/2) + 1
    
- T(n/2) = T(n/4) + 1
    
- T(n/4) = T(n/8) + 1
    
- ……
    
- 直到 T(1) = O(1)（递归出口）
    

总共展开了多少次？因为每次除以2，所以是 **log₂(n)** 层。  
所以：T(n) = log₂(n) * 1 + O(1) = **O(log n)**

**结论**：二分查找的时间复杂度是 **O(log n)**。

---

#### （2）斐波那契数列 —— 每次都分叉，指数爆炸

c

int fib(int n) {
    if (n <= 1) return n;                // O(1)
    return fib(n-1) + fib(n-2);          // 调用了两次！
}

**递归方程建模**：

- `a = 2`：每次递归调用**两次**自身。
    
- `b = 1`：数据规模不是除以某个数，而是**减1和减2**（`n-1` 和 `n-2`），所以不适用 `n/b` 公式，但我们可以用**递归树**来分析。
    
- `f(n) = O(1)`：每层只做加法。
    

T(n)=T(n−1)+T(n−2)+O(1)T(n)=T(n−1)+T(n−2)+O(1)

**解方程（递归树法）**：

画一棵递归树，你会发现：

- 第1层（根节点）：1个节点。
    
- 第2层：2个节点（`fib(n-1)` 和 `fib(n-2)`）。
    
- 第3层：4个节点（每个又分两个）。
    
- 第k层：**2^(k-1)** 个节点。
    

直到最底层 `n=0` 或 `n=1`，大约有 `n` 层。  
所以总节点数 ≈ 1 + 2 + 4 + 8 + ... + 2^(n-1) = **2^n - 1**。

**结论**：斐波那契递归的时间复杂度是 **O(2^n)**（指数爆炸！）。

> **残酷现实**：`fib(50)` 就能让电脑算到天荒地老。这也是为什么现实中绝不用这种写法，而是用**迭代**（O(n)）或**带备忘录的递归**（O(n)）。

#### （3）归并排序 —— 分而治之，合并收尾

c

void mergeSort(int arr[], int left, int right) {
    if (left >= right) return;                  // O(1)
    int mid = (left + right) / 2;               // O(1)
    mergeSort(arr, left, mid);                  // 左半部分
    mergeSort(arr, mid+1, right);               // 右半部分
    merge(arr, left, mid, right);               // O(n) 合并两个有序数组
}

**递归方程建模**：

- `a = 2`：每次递归调用**两次**自身（左半和右半）。
    
- `b = 2`：数据规模每次变成一半（`n/2`）。
    
- `f(n) = O(n)`：除了递归外，还有一个 **merge** 操作，需要 O(n) 时间把两个有序数组合并。
    

T(n)=2⋅T(n2)+O(n)T(n)=2⋅T(2n​)+O(n)

**解方程（主定理法——最快捷的方式）**：

这里需要用到一个神器——**主定理（Master Theorem）**。它专门用于解形如 `T(n) = a*T(n/b) + f(n)` 的递归方程。

我们比较 `f(n)` 和 `n^(log_b a)` 的大小：

- 这里 `a=2`, `b=2`，所以 `log_b a = log₂2 = 1`，因此 `n^(log_b a) = n^1 = n`。
    
- `f(n) = O(n)`，它与 `n^(log_b a)` **同阶**（都是 O(n)）。
    

套用主定理的**情况二**（当 `f(n) = Θ(n^(log_b a) * log^k n)`，且 `k=0` 时）：  
T(n) = Θ( n^(log_b a) * log n ) = Θ( n * log n )

**结论**：归并排序的时间复杂度是 **O(n log n)**，这是比较排序的“天花板”。

### 3. 万能三步法（拿去直接用）

当你遇到任何递归算法，按下面三步走，保证你不乱：

|步骤|操作|说明|
|---|---|---|
|**第一步**|写出递归方程 `T(n) = a*T(n/b) + f(n)`|搞清楚 `a`（分了几叉）和 `b`（每次缩小几倍），以及当前层的 `f(n)`。|
|**第二步**|计算 `n^(log_b a)`|这是递归树的总分支数带来的“基础耗时”。|
|**第三步**|比较 `f(n)` 和 `n^(log_b a)`|- 如果 `f(n)` 小得多 → **T(n) = O(n^(log_b a))**  <br>- 如果 `f(n)` 同阶 → **T(n) = O(n^(log_b a) * log n)**  <br>- 如果 `f(n)` 大得多 → **T(n) = O(f(n))**|
|**（备选）**|画递归树|如果递归方程写不出来（比如每次减1而非除以一个数），就用递归树逐层累加。|

## 分支五：递归算法时间复杂度分析
### （一）核心工具：递归方程
- T(n) = a * T(n/b) + f(n)
  - a：递归分叉数
  - n/b：子问题规模
  - f(n)：当前层额外开销
### （二）三大解法
- **代入法**：把 T(n/2)、T(n/4) 展开，找规律（适合 a=1 的情形）
- **递归树法**：画出调用树，逐层累加节点数（适合分叉数不规律的情形）
- **主定理（Master Theorem）**：直接套公式（最适合考试，最快）
### （三）常见复杂度对照表
- O(log n)：二分查找、平衡二叉树的查找
- O(n)：遍历链表、二叉树的前/中/后序遍历
- O(n log n)：归并排序、快速排序（理想情况）
- O(n²)：冒泡排序、快速排序（最坏情况）
- O(2^n)：斐波那契、穷举子集
