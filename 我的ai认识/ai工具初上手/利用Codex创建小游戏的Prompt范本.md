# 金币远征》游戏设计文档（GDD）

> 暂定名称：金币远征  
> 游戏类型：2D 横版卷轴平台跳跃  
> 目标平台：Web 浏览器  
> 开发范围：单人、纯前端、无需安装

## 1. 游戏概述

### 核心玩法

玩家控制角色在横向卷轴关卡中前进，通过移动和跳跃：

- 跨越坑洞、尖刺等障碍。
- 躲避或踩踏敌人。
- 收集沿途金币。
- 抵达关卡终点。
- 在生命耗尽前完成全部关卡。

基础游戏循环：

**进入关卡 → 移动与跳跃 → 躲避危险 → 收集金币 → 到达终点 → 结算并进入下一关**

### 游戏目标

- 主要目标：安全抵达每关终点。
- 次要目标：收集尽可能多的金币。
- 挑战目标：以更短时间、零死亡或全金币完成关卡。

### 目标受众

- 喜欢轻量休闲游戏的普通玩家。
- 熟悉经典横版平台玩法的玩家。
- 希望通过浏览器快速游玩的用户。
- 建议年龄：6 岁以上。

### 单局体验

- 每关预计用时：2～5 分钟。
- 首个版本建议包含：3 个关卡。
- 完整流程预计用时：10～15 分钟。
- 难度曲线：教学关 → 综合挑战关 → 高难终点关。

## 2. 核心机制

### 2.1 移动

- 玩家可以向左或向右移动。
- 加速和减速应略带惯性，但保持响应灵敏。
- 角色松开方向键后快速停下，避免操作过于“滑”。
- 镜头主要跟随玩家向右移动，并限制在关卡边界内。
- 玩家可以少量向左返回，但整体鼓励向右推进。

建议初始参数：

|参数|建议值|
|---|---|
|最大水平速度|220 px/s|
|地面加速度|1,500 px/s²|
|空中控制力|地面的 70%|
|减速度|2,000 px/s²|

具体数值可在试玩时调整。

### 2.2 跳跃

- 角色仅在接触地面或平台时正常起跳。
- 短按跳跃键执行小跳，长按执行较高跳跃。
- 采用重力加速度，使跳跃形成明确的上升与下落阶段。
- 下落速度可略快于上升速度，让操作更加利落。
- 建议加入两项操作宽容机制：
    - **土狼时间**：离开平台后约 0.1 秒内仍可跳跃。
    - **跳跃预输入**：落地前约 0.1 秒按下跳跃，落地后自动起跳。

第一版不加入二段跳、冲刺或攀墙，保持规则简单。

### 2.3 碰撞

使用矩形包围盒进行碰撞检测。

需要检测的对象包括：

- 地面和固定平台。
- 可从下方穿过的单向平台。
- 坑洞与关卡边界。
- 尖刺等致命障碍。
- 敌人。
- 金币和终点。
- 可选的弹簧或移动平台。

碰撞结果：

- 落在平台顶部：停止下落并进入站立状态。
- 撞到墙壁：停止对应方向的水平移动。
- 撞到天花板：停止上升并开始下落。
- 从上方踩到敌人：消灭敌人，玩家获得小幅反弹。
- 从侧面或下方接触敌人：玩家受伤或死亡。
- 掉出关卡底部：损失一条生命并从检查点重生。

### 2.4 生命与失败

MVP 建议使用简单的三条生命制：

- 每局初始拥有 3 条生命。
- 接触尖刺、敌人或跌落时损失 1 条生命。
- 受伤后从最近检查点重生。
- 生命归零后显示“游戏结束”，允许重新开始当前关卡。
- 进入下一关时恢复生命，降低整体挫败感。

为了简化首版开发，角色不设置复杂生命值或装备系统。

### 2.5 敌人

首个版本建议包含两类敌人：

#### 巡逻怪

- 在平台上左右移动。
- 遇到墙壁或平台边缘时转向。
- 可以被玩家从上方踩踏消灭。
- 适合用于介绍基础敌人机制。

#### 跳跃怪

- 在固定区域周期性跳跃。
- 行动节奏明确，玩家可以观察并穿过。
- 可以被踩踏消灭。
- 用于中后期关卡增加时机挑战。

敌人不需要复杂寻路或远程攻击。所有敌人应具有明显的待机、移动和被消灭反馈。

### 2.6 收集物

#### 金币

- 接触后立即收集。
- 每枚金币增加分数并播放动画与音效。
- 金币可用于引导玩家发现安全路线或隐藏区域。
- 关卡结算时显示“已收集数量 / 关卡总数”。

#### 可选收集物：大金币

- 每关设置 1～3 枚。
- 放置在较危险或隐蔽的位置。
- 用于鼓励探索和重复游玩。
- 不影响正常通关。

MVP 必须实现普通金币；大金币可以作为扩展内容。

### 2.7 关卡结构

每关由以下区域组成：

1. **起点安全区**：让玩家熟悉控制。
2. **机制教学区**：通过简单地形介绍本关机制。
3. **组合挑战区**：将平台、敌人和障碍组合使用。
4. **检查点**：保存当前重生位置。
5. **终点挑战区**：提供本关最高强度的短挑战。
6. **终点旗帜或传送门**：触发关卡结算。

建议首版关卡：

|关卡|主题|主要内容|
|---|---|---|
|第 1 关|草地|移动、跳跃、金币、巡逻怪|
|第 2 关|黄昏山谷|单向平台、尖刺、跳跃怪、检查点|
|第 3 关|遗迹|移动平台、连续跳跃、综合挑战|

关卡应避免要求玩家进行看不到落点的“盲跳”。危险区域需要通过颜色、动画或地形轮廓提前提示。

### 2.8 计分与结算

建议计分规则：

- 普通金币：100 分。
- 大金币：500 分。
- 消灭敌人：200 分。
- 通关奖励：1,000 分。
- 剩余时间可转换为额外分数。

结算界面显示：

- 是否通关。
- 收集金币数量。
- 消灭敌人数量。
- 通关时间。
- 本关得分。
- “下一关”或“重新挑战”按钮。

分数仅用于反馈和挑战，不涉及联网排行榜。

## 3. 美术风格建议

### 推荐方向：明快像素风

建议采用现代化的 16-bit 像素风：

- 使用鲜明、易区分的色彩。
- 角色和敌人拥有清晰轮廓。
- 地面、平台、障碍物具有明确的视觉边界。
- 每个动作使用少量关键帧动画，降低制作成本。
- 以整数倍缩放像素素材，避免画面模糊。

建议素材基准：

- 逻辑瓦片尺寸：32 × 32 px。
- 玩家尺寸：约 32 × 48 px。
- 基础动画：待机、奔跑、跳跃、下落、受伤、胜利。
- 敌人动画：移动、攻击或跳跃、被消灭。

### 色彩与场景

- 前景使用较高饱和度和对比度。
- 背景使用较低饱和度，避免干扰游戏对象。
- 危险物使用红色、紫色或高对比轮廓。
- 金币使用明亮黄色，并配合闪烁动画。
- 可使用两到三层视差背景增强横向移动感。

### 参考方向

可参考经典 2D 平台游戏的：

- 清晰的平台轮廓。
- 通过金币排列引导跳跃路线。
- 敌人动作的预判性。
- 不同区域之间的色彩分层。
- 短促而明确的动作反馈。

角色、敌人、场景名称及造型应采用原创设计，避免直接复制现有游戏的角色、素材或关卡。

### 备选方向：扁平矢量风

如果团队缺少像素美术经验，可改用几何扁平风：

- 通过 Canvas 图形或简单 SVG 绘制素材。
- 使用圆角矩形、圆形和纯色色块。
- 动画制作简单，适合快速原型。
- 缺点是经典平台游戏氛围相对较弱。

MVP 推荐先使用扁平占位素材验证玩法，玩法稳定后再替换为像素素材。

## 4. 控制方案

### 键盘控制

|操作|按键|
|---|---|
|向左移动|`A` 或 `←`|
|向右移动|`D` 或 `→`|
|跳跃|`W`、`↑` 或 `Space`|
|暂停|`Esc` 或 `P`|
|重新开始关卡|`R`|
|确认菜单|`Enter` 或 `Space`|

浏览器默认滚动行为需要在游戏获得焦点后禁用，避免方向键和空格键滚动页面。

### 触屏控制

横屏模式下显示三个半透明虚拟按钮：

- 左下角：向左。
- 左下角：向右。
- 右下角：跳跃。

触屏要求：

- 支持同时按住方向和跳跃。
- 按钮尺寸至少为 64 × 64 CSS 像素。
- 按钮按下时显示高亮反馈。
- 松开、滑出按钮或触摸被取消时立即清除输入状态。
- 尽量阻止游戏区域内的页面缩放、选中文本和滚动。
- 屏幕过窄或处于竖屏时提示玩家旋转设备。

### 通用交互

- 开始前显示简短操作说明。
- 第 1 关通过安全场景逐步引导玩家。
- 游戏暂停或页面失去焦点时停止更新。
- 用户首次交互后再播放声音，以符合浏览器自动播放限制。

## 5. 技术选型建议

### 最简单技术栈

采用纯原生前端：

- **HTML5**：页面、菜单和游戏画布。
- **CSS3**：页面布局、触屏按钮和界面样式。
- **JavaScript ES Modules**：游戏逻辑。
- **Canvas 2D API**：场景、角色和界面绘制。
- **Web Audio API 或 `<audio>`**：音效与背景音乐。
- **JSON 或 JavaScript 对象**：关卡数据。

无需使用 React、Vue、后端、数据库或重量级游戏引擎。

### 建议项目结构

```
index.html
styles.css
src/
  main.js
  game.js
  input.js
  physics.js
  entities.js
  level.js
assets/
  images/
  audio/
levels/
  level-1.json
  level-2.json
  level-3.json
```

开发初期也可以合并文件，但正式实现时应至少分离输入、物理、关卡和主循环逻辑。

### 核心技术方案

- 使用 `requestAnimationFrame` 驱动游戏循环。
- 使用固定时间步长更新物理，降低不同刷新率造成的速度差异。
- 使用 Canvas 逻辑分辨率，例如 960 × 540。
- 根据浏览器窗口等比缩放画布。
- 使用瓦片网格保存关卡地形。
- 使用 AABB 矩形碰撞检测。
- 先分别处理水平和垂直移动，减少卡墙问题。
- 使用摄像机偏移量实现横向卷轴。
- 使用有限状态管理开始、游玩、暂停、结算和失败界面。
- 使用 `localStorage` 保存最高分、已解锁关卡及音量设置。

### 运行与发布

最终版本应能通过静态网站运行，可部署到 GitHub Pages、Netlify 或任意静态文件服务。

开发时不应依赖后端服务。若使用 ES Modules，建议通过简单的本地静态服务器开发；发布后玩家只需打开网页链接。

## 6. 成功指标：什么叫“做完了”

### MVP 完成标准

满足以下条件即可认为首个可玩版本完成：

- 玩家可以使用键盘和触屏进行左右移动与跳跃。
- 角色能够稳定站立在地面和平台上，不会明显穿墙或穿地。
- 镜头可以随角色平滑横向滚动。
- 至少包含 3 个可从起点通关至终点的关卡。
- 包含地面、平台、坑洞、尖刺和检查点。
- 至少包含 2 种行为不同的敌人。
- 玩家可以踩踏敌人，也会因错误接触而损失生命。
- 金币可以被收集并正确计数。
- 玩家死亡后可以从检查点重生。
- 生命耗尽后可以重新开始关卡。
- 到达终点后显示结算界面，并可进入下一关。
- 包含开始、暂停、通关和游戏结束状态。
- 刷新页面后能够保留最高分或关卡进度。
- 桌面端与常见手机浏览器均可正常游玩。
- 不需要账号、安装程序、后端或额外插件。

### 体验验收标准

- 新玩家无需阅读长说明，1 分钟内能够理解移动和跳跃。
- 所有必经跳跃在正常操作下都可以稳定完成。
- 不出现玩家无故卡入平台、穿透地面或无法重生的问题。
- 关卡开始后能持续保持接近 60 FPS；普通移动设备最低不低于 30 FPS。
- 页面失焦、暂停或切换标签页后，游戏不会继续造成意外死亡。
- 触屏按钮支持方向键与跳跃键同时按下。
- 游戏画面在不同屏幕尺寸下保持正确比例。
- 所有素材均为原创、已获授权或采用允许商用的开放许可。

### 不属于首版完成条件

以下内容可留作后续版本：

- 联网排行榜。
- 多人模式。
- 账号系统和云存档。
- 关卡编辑器。
- 商店、角色成长或复杂道具系统。
- **Boss 战。**
- 程序化关卡。
- **完整剧情与过场动画。**

### 默认假设

- 游戏为单人游玩。
- 首版只提供一个可操作角色。
- 默认横屏显示，逻辑分辨率为 960 × 540。
- 首版包含 3 个关卡，目标总流程为 10～15 分钟。
- 采用原创像素风或扁平占位素材。
- 所有进度仅保存在当前浏览器的 `localStorage` 中。
