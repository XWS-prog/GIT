### 一、简要解释

- **System Prompt（系统提示词）**：这是**开发者和平台**给AI设定的“**底层人设、规则和世界观**”。它定义了AI的身份、能力边界、回复格式、价值观禁忌以及行为逻辑。它在整个对话生命周期中始终保持高优先级，用户通常无法修改（或仅能在设定框架内互动）。
    
- **User Prompt（用户提示词）**：这是**当前用户**针对**本次具体任务**发出的“**指令或问题**”。它承载着用户当下的具体需求（如写一段代码、翻译一句话或进行头脑风暴），是驱动AI执行特定动作的直接触发器。
    

---

### 二、功能矩阵对标 (Function Matrix)

| 对比维度          | **System Prompt（系统提示词）**                                              | **User Prompt（用户提示词）**                            |
| ------------- | --------------------------------------------------------------------- | ------------------------------------------------- |
| **1. 定位与角色**  | **“宪法/剧本”**：设定AI的身份、性格和底层规则。                                          | **“台词/行动指令”**：用户下达的具体待办任务。                        |
| **2. 设定者**    | 开发者、产品经理或平台管理员（**B端/平台主导**）。                                          | 最终用户或调用API的开发者（**C端/调用方主导**）。                     |
| **3. 生效周期**   | **长时记忆/全局生效**：贯穿整个多轮对话会话（Session）。                                    | **即时生效/单次触发**：仅针对当前这一轮请求产生效果。                     |
| **4. 优先级与权重** | **最高优先级（Root Instruction）**：通常被锁定，权重远高于用户指令，用于防止越狱和角色崩塌。              | **相对权重较低**：必须在遵守System Prompt设定的边界内执行。            |
| **5. 内容重点**   | 侧重**“如何做”**：输出格式（JSON/Markdown）、语气（专业/幽默）、伦理红线（拒绝违法内容）、知识范围（只参考上传文档）。 | 侧重**“做什么”**：具体的业务数据、需要分析的文章内容、待解决的问题描述。           |
| **6. 变量特征**   | **高度静态**：极少变动，写死后基本固化（除非后台调整策略）。                                      | **高度动态**：每轮对话内容都不同，极具随机性。                         |
| **7. 安全控制**   | **核心安全闸门**：负责拦截有害请求，确保内容合规（Alignment）。                                | **风险来源**：可能包含越狱（Jailbreak）尝试，试图覆盖System Prompt规则。 |
| **8. 典型示例**   | _“你是一个资深财务分析师，回复时仅输出JSON格式，且不得涉及政治敏感话题。”_                             | _“请分析附件中Q3财报的营收增长率，并转化为JSON输出。”_                  |

### 三、协同工作流逻辑（供参考）

在实际大模型推理中，两者的拼接顺序通常为：  
***SystemPrompt* + 历史对话 + *UserPrompt***

- **System** 画好“圈”（边界和风格）；
    
- **User** 在“圈”内提出具体请求；
    
- 模型在遵守 **System** 底线的前提下，优先满足 **User** 的显性需求。
